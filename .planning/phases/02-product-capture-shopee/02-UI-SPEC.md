# Phase 2 — UI Design Contract
# Chrome Extension Popup: Product Capture (Shopee)

> Visual and interaction contract for the Chrome MV3 extension toolbar popup.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Surface scope:** Extension toolbar popup ONLY (360–400px wide, max 600px tall).
> No web dashboard in this phase. The popup is a self-contained HTML page rendered
> by WXT inside Chrome's extension popup window.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none (vanilla TS + Tailwind CDN) | RESEARCH.md open question resolved — see Framework Decision below |
| Preset | not applicable | — |
| Component library | none — hand-rolled with Tailwind utilities | decision |
| Icon library | Lucide icons (SVG inline, 20×20) | ui-ux-pro-max no-emoji rule |
| Font | Noto Sans Thai (Google Fonts CDN) | ui-ux-pro-max — Thai multilingual, modern, readable |
| Tailwind version | 4.3.1 via CDN play.tailwindcss.com script | CLAUDE.md stack; CDN used in popup HTML only |

### Framework Decision (resolves RESEARCH.md open question A6)

**Recommendation: Vanilla TypeScript + Tailwind CSS via CDN.**

Rationale:
- Popup is a fixed ~400px surface — no routing, no component tree needed.
- React would add ~200KB to the popup bundle; CDN Tailwind adds ~0KB runtime overhead.
- WXT supports vanilla TS natively via `entrypoints/popup/index.html` + `main.ts`.
- Brand consistency with Phase 4 (Next.js) is achieved through shared design tokens
  (same color hex, same Noto Sans Thai font, same spacing scale) — NOT through shared
  component code. The executor uses the exact same hex values in both contexts.
- **Implication for planner:** Scaffold popup as `entrypoints/popup/` with `index.html`
  referencing Tailwind CDN + `main.ts` as the entry. No React, no Vite React plugin
  needed in the extension workspace.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline element gaps |
| sm | 8px | Input padding-y, gap between form label and input |
| md | 16px | Section padding (popup sides), gap between form rows |
| lg | 24px | Gap between major sections (header → body, body → footer) |
| xl | 32px | Reserved for future; not used in popup surface |
| 2xl | 48px | Reserved for future; not used in popup surface |
| 3xl | 64px | Not used in popup |

**Popup-specific constraints:**
- Popup width: fixed 380px (`width: 380px` on `<body>`)
- Popup max-height: 580px (`max-height: 580px; overflow-y: auto` on main content area)
- All buttons: minimum 44×44px touch target (ui-ux-pro-max CRITICAL rule)
- Form input height: 36px (`h-9` in Tailwind) — compact for data-dense form
- Field count badge: 4px vertical padding, 8px horizontal padding

Exceptions:
- "N/N fields captured" badge uses 4px/8px padding (xs/sm) — smaller than standard buttons

## Typography

Single font family throughout: **Noto Sans Thai** — covers Thai and Latin characters
in one typeface, no font-fallback mismatch between field labels and Thai copy.

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Heading (popup title) | 16px | 600 semibold | 1.2 | `text-base font-semibold leading-tight` |
| Body / field labels | 13px | 400 regular | 1.5 | `text-[13px] font-normal leading-normal` |
| Input text | 13px | 400 regular | 1.5 | `text-[13px] font-normal` |
| Caption / helper / badge | 11px | 400 regular | 1.4 | `text-[11px] font-normal leading-snug` |

**Rationale:** 13px body is readable at popup scale (compact but not cramped). 16px
heading is visually distinct without being oversized. Only 2 weights used (400, 600).

**Google Fonts import (in popup/index.html `<head>`):**
```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+Thai:wght@400;600&display=swap" rel="stylesheet">
```
Then set on `<body>`: `style="font-family: 'Noto Sans Thai', sans-serif;"`

## Color

### Palette Origin
Derived from ui-ux-pro-max Productivity Tool palette (teal focus + orange CTA), adjusted
for Thai affiliate tool context. Primary teal communicates reliability and data clarity
— appropriate for a scoring/capture tool. Orange CTA is high-contrast for Save/Capture
actions. The palette carries forward to Phase 4 dashboard (same hex values in
`tailwind.config.ts`).

| Role | Hex | Tailwind Equivalent | Usage |
|------|-----|---------------------|-------|
| Dominant (60%) | `#F0FDFA` | `teal-50` | Popup background, input backgrounds |
| Secondary (30%) | `#CCFBF1` | `teal-100` | Header bar, section dividers, badge background |
| Primary brand | `#0D9488` | `teal-600` | Heading text, focus rings, active states |
| Accent (10%) | `#F97316` | `orange-500` | PRIMARY CTA: "จับข้อมูล" button, "บันทึก" button ONLY |
| Text primary | `#134E4A` | `teal-900` | Body text, field labels, input text |
| Text muted | `#5EEAD4` → use `#4B7280` | `gray-600` | Helper text, field count denominator, placeholder |
| Border | `#99F6E4` | `teal-200` | Input borders, dividers |
| Success | `#10B981` | `emerald-500` | Success state banner, saved confirmation |
| Warning | `#F59E0B` | `amber-500` | "0/N fields captured" warning icon and border |
| Destructive | `#EF4444` | `red-500` | Error state (backend offline banner) ONLY |
| White surface | `#FFFFFF` | `white` | Form inputs, cards within the popup |

**Accent reserved for:** The "จับข้อมูล" (Capture) button and the "บันทึก" (Save) button
ONLY. No other element uses `#F97316`. All secondary actions (Try again, Cancel) use
teal-600 text on transparent/teal-100 background.

**Contrast compliance:** `#134E4A` on `#F0FDFA` = 8.9:1 (exceeds 4.5:1 AA).
`#FFFFFF` on `#F97316` = 3.1:1 — use `font-semibold` on button text to compensate;
button is interactive (not body text), WCAG 3:1 applies for UI components.

## State Screens

The popup has exactly 5 states. Each maps to a distinct screen layout within the same
380px popup shell. Transitions between states are instant (no animation); loading
state uses a spinner inside the button.

### State 1: Idle / Initial

**When shown:** Popup opens fresh; no capture in progress.

**Layout (top to bottom):**
```
┌─────────────────────────────────────┐  <- bg-teal-50
│  [A] Header: "Affilytics"  v[icon]  │  <- bg-teal-100, h-10, px-4
│─────────────────────────────────────│
│                                     │  <- px-4 py-4
│  [B] Primary CTA button             │
│      [Lucide: camera icon]           │
│      "จับข้อมูล"                    │  <- full-width, h-11, orange-500
│                                     │
│  ── หรือ ──────────────────────────  │  <- text-[11px] text-gray-400 my-3
│                                     │
│  [C] URL input                      │
│      label: "วางลิงก์สินค้า"         │
│      [input field]                  │  <- h-9 border-teal-200
│      [ปุ่ม "ใช้ลิงก์"] (small btn)   │  <- teal-600 text, teal-100 bg
│                                     │
└─────────────────────────────────────┘
```

### State 2: Review Form (Core Surface)

**When shown:** After successful Capture (or after URL paste). Content script returned
>0 fields OR operator pasted a URL.

**Layout (top to bottom, scrollable):**
```
┌─────────────────────────────────────┐  <- bg-teal-50
│  [A] Header + badge                 │  <- bg-teal-100, h-10, px-4
│      "ตรวจสอบข้อมูล"  [6/8 ฟิลด์]   │
│─────────────────────────────────────│
│                                     │  <- scrollable area, max-h: ~460px
│  [B] Form (8 editable fields)       │  <- px-4 pt-3
│                                     │
│      ชื่อสินค้า *                   │  <- label 13px, asterisk teal-600
│      [input]                        │
│                                     │
│      ราคา (฿) *         ส่วนลด (%)  │  <- 2-column row
│      [input]             [input]    │
│                                     │
│      คะแนน (0-5)        รีวิว       │  <- 2-column row
│      [input]             [input]    │
│                                     │
│      ยอดขาย              ร้านค้า    │  <- 2-column row
│      [input]             [input]    │
│                                     │
│      URL สินค้า *                   │  <- full-width
│      [input, readonly with copy btn]│
│                                     │
│─────────────────────────────────────│
│  [C] Footer actions                 │  <- bg-white border-t border-teal-100
│      [ยกเลิก]        [บันทึก]       │  <- h-11 each, sticky bottom
└─────────────────────────────────────┘
```

**"N/N fields captured" badge:** pill shape, bg-teal-100, text-teal-600 (13px semibold).
Shows integer count of non-null fields out of total 8 fields. Auto-populated fields
shown with standard input styling; empty fields shown with `border-amber-300
bg-amber-50` as a soft visual cue (not an error — operator may fill or leave empty).

│       กรุณาลองใหม่"                 │
│      bg-amber-50 border-amber-300   │  <- rounded-lg p-3
│                                     │
│  [C] "ลองใหม่อีกครั้ง" button       │  <- full-width h-11 teal-600 text

### State 4: Backend Offline Error (D-08)

**When shown:** Save was pressed; fetch to localhost returned network error.

**Layout:** State 2 form is preserved EXACTLY (no data loss). An error banner is
prepended above the footer.

```
│  ... review form unchanged ...      │
│─────────────────────────────────────│
│  [Error banner]                     │  <- bg-red-50 border-red-300 rounded-lg
│  [Lucide: wifi-off red]             │     mx-4 mb-2 p-3
│  "เชื่อมต่อ backend ไม่ได้"         │  <- text-red-700 font-semibold 13px
│  "รัน `bun dev` แล้วกด บันทึก อีก  │  <- text-[11px] text-red-600
│   ครั้ง"                            │
│─────────────────────────────────────│
│  [ยกเลิก]        [บันทึก]           │  <- same footer, Save re-enabled
└─────────────────────────────────────┘
```

### State 5: Success Confirmation

**When shown:** Save returned `{ ok: true }` from backend.

**Layout:**
```
┌─────────────────────────────────────┐
│  [A] Header: "Affilytics"           │  <- bg-teal-100, h-10, px-4
│─────────────────────────────────────│
│                                     │  <- px-4 py-8 text-center
│  [Lucide: check-circle emerald-500] │  <- w-12 h-12 mx-auto mb-3
│                                     │
│  "บันทึกสำเร็จ!"                    │  <- text-base font-semibold text-teal-900
│  "สินค้าถูกเพิ่มในระบบแล้ว"        │  <- text-[13px] text-gray-600 mt-1
│                                     │
│  [จับสินค้าใหม่] button             │  <- full-width h-11 orange-500, mt-4
└─────────────────────────────────────┘
```

Auto-close after 3 seconds and reset to State 1. Or operator clicks "จับสินค้าใหม่"
immediately.

## Loading / Async States

| Action | Loading Treatment |
|--------|------------------|
| "จับข้อมูล" pressed | Disable button, replace icon with `animate-spin` Lucide `loader-2`, label: "กำลังอ่าน..." |

| "ลองใหม่อีกครั้ง" pressed | Same as Capture: spinner + "กำลังอ่าน..." |

## Accessibility Contract

All rules sourced from ui-ux-pro-max CRITICAL rules.

| Rule | Implementation |
|------|---------------|
| Touch targets ≥ 44×44px | All buttons: `h-11` (44px) minimum. URL "ใช้ลิงก์" button: `h-9 px-4` — exception accepted (compact inline action); add `min-w-[44px]` |
| Form labels with `for` | `<label for="field-name">` on every input; IDs: `input-name`, `input-price`, `input-discount`, `input-rating`, `input-reviews`, `input-sales`, `input-shop`, `input-url` |
| Error announced | Error/warning banners use `role="alert"` so screen readers announce them |
| Loading state announced | Loading button uses `aria-busy="true"` and `aria-label="กำลังโหลด..."` |
| Focus rings | `focus:ring-2 focus:ring-teal-500` on all inputs and buttons; do not remove outline |
| Keyboard navigation | Tab order: Capture → URL input → Use URL → (in form) all 8 fields top-to-bottom → Cancel → Save |
| Color not sole indicator | Empty fields use amber border + amber background (not color alone) — border pattern is a secondary indicator |
| Minimum contrast | Body text `#134E4A` on `#F0FDFA`: 8.9:1. Error text `#B91C1C` on `#FEF2F2`: 5.4:1. All pass AA. |
| `prefers-reduced-motion` | Spinner animation wraps with `@media (prefers-reduced-motion: reduce) { animation: none }` |
